# 记忆怎么处理 —— 双记忆共存 + 老鱼/新鱼两条路

> 这份文档回答两个问题：
> ① 宿主已经有日记了，脑里再存一份，冲突怎么办？
> ② 已经养了很久的老鱼，怎么搬进来？新鱼又怎么开始？

---

## 一、四套记忆，各管什么

| 记忆 | 存在哪 | 内容 | 参与检索吗 |
|---|---|---|---|
| **脑记忆** | `brain.json` | 带情绪的经历、印象、卡片、口味 | ✅ **只有它参与** |
| **她的日记** | `brains/<id>/days/*.md` | **她自己写的**，用她自己的口吻 | ✅ 写日记会进记忆 |
| 宿主日记 | `days/*.md` | 流水账：今天发生了什么 | ❌ 归档 |
| 经验 | `experience.jsonl` | 学到的东西 | ❌ 归档 |
| 跨平台 | `cross-platform.jsonl` | 各平台事件 | ❌ 归档 |

**关键**：不是"两份都记"，是**脑是主档，其余是归档**。

用户问「你记得吗」——只有脑里有的才算"记得"。日记里有、脑里没有，那是"好像有过这回事"。

这不是缺陷。人的记忆本来就分层：**记得住的是有情绪的，记不住的是流水。**

---

## 二、三种共存策略，选一种

### 策略 A：脑为主，日记归档（推荐）

- 脑负责"她记得什么"
- 日记继续写，但**不灌进脑**，只在人工回溯时查
- 优点：只有一个真相来源，不会出现两个答案
- 缺点：日记里的东西她"想不起来"

### 策略 B：一次性搬迁，之后各自独立

- 把日记**搬一次**进脑（`migrate`），之后日记停写或只写不读
- 适合：老鱼刚接进来，想让过去也算数
- 缺点：搬进来的都是 `source:'import'`，情绪值一律 0（日记里没有）

### 策略 C：全量整合，之后只剩一份（你想要的这个）

- 把 `days/*.md`、`experience.jsonl`、`cross-platform.jsonl` **全部搬进脑**
- 搬完原文件改名 `.migrated`，宿主停写这些文件
- 从此**只有一份记忆**，不会再有两个答案
- 代价：见下面第七节，先说清楚再决定

**如果只想要"简单、不分层"——选 C。**

## 三、老鱼：把过去搬进来

### 第 1 步：先看会搬多少（不写任何东西）

```bash
npx feiyu migrate ./days/2026-11-18.md --format days --dry-run
```

输出：

```
格式 days　解析出 2 条　重复 0 条　将导入 2 条
时间跨度 2026-11-18 → 2026-11-18
跳过 1 行：
  第 4 行 认不出格式（跳过，不猜）
```

**认不出来就跳过，不猜。** 搬迁宁可少搬，不能瞎搬。

### 第 2 步：确认没问题，真搬

```bash
npx feiyu migrate ./days/2026-11-18.md --format days
```

### 第 3 步：体检

```bash
npx feiyu status
npx feiyu brief          # 看看"此刻的她"像不像原来那条鱼
```

或者代码里：

```js
identityCheck('old')
// → { memory:{episodes:120,people:8}, narrative:true, relation:{...}, verdict:'是她' }
```

### 支持的三种格式

| format | 长什么样 |
|---|---|
| `jsonl` | 一行一条 `{"sender":"谁","text":"说了什么","time":1763500000000}` |
| `days` | 日记式：`- 某人：说了什么`，日期靠 `## 2026-11-18` 标题 |
| `generic` | JSON 数组 `[{who,text,at}]` |

**没有日期头就不编时间**——那几条 `at` 留 0，宁可空着也不假装知道几号。

### 搬迁会丢什么

| 会保留 | 会丢 |
|---|---|
| 谁说的、说了什么 | 当时的情绪（日记里通常没有） |
| 时间（有日期头的话） | 语气、上下文 |
| `source:'import'` 标记 | — |

**搬进来的是"发生过"，不是"她感受到"。** 这部分只能靠以后的经历慢慢补。

## 四、新鱼：从零开始

```js
const fy = createBrain({ id: 'new', dataDir, roleDir, cardText, cardName: '新鱼' })
```

- 记忆空、情绪词表空、关系只有创建时那一条
- 第一次对话开始 `observe`，权重才会动
- **不需要搬迁，也不要预填**——预填等于给她一段"别人的记忆"

新鱼唯一的坑：**别把老鱼的 `brainId` 复用**。同一个 id 会把两段人生搅在一起。

## 五、30 天不是删除，是「压扁」

这是最容易误解的一条。**计时从「最后一次被提起」算，不是从「存进来的时间」算。**

```
0 ──────────── 30 天 ──────────── 90 天 ────────→
   完整记忆        压扁成一句"大概"        遗忘
   （细节都在）    （还检索得到，没有细节）  （认知上不存在了）
        ↑                ↑                    ↑
     有人提 → 续命    有人提 → 变清晰       有人提 → 已经没了，
                     计时再归零              只能从 archive.jsonl 找
```

实测：

```
搬完 4 条:       [清晰] 第一个话题 / 第二个话题 / 第三个话题 / 别的事
第40天没人提:    [模糊] （记不清了）扶摇：第一个话题…前后还有 2 件
                 [模糊] （记不清了）访秋辞：别的事
第100天:         0 条（遗忘 2 条，原文进了 archive.jsonl）
```

**同一个人同一天的几件事，会合并成一条"大概"。** 不是丢，是变模糊。

### 什么算「被提起」

| 动作 | 算不算 |
|---|---|
| 有人又聊到这件事（`observe` 命中） | ✅ 续命 |
| 她自己想起来（`wake` 检索命中） | ✅ 续命，而且从"模糊"变回"清晰" |
| 手动 `touch(id, key)` | ✅ |
| 只是躺在 `brain.json` 里 | ❌ 计时继续走 |

**一直有人问的事，永远走不到第二层。** 这就是"反复去问才会保留"。

### 人设也一样

命题（units）的衰减不是"每天掉一点"，是**长期没人碰才掉**：

```
最后一次被碰到 → 30 天内还有人聊到 → 不掉
               → 30 天没人碰      → 开始每天 ×0.999
               → 掉到 0.15        → 蜕皮成"我以前……"
```

`identity` 永不衰减，永远不掉。

### 四个档位

| `ttlPolicy` | 行为 |
|---|---|
| `hard`（默认） | 上面那套两层老化，原文进 `archive.jsonl` |
| `summarize` | 老化时额外压一张卡片 |
| `archive` | 同 `hard`（保留兼容） |
| `off` | 永不压扁、永不遗忘——调试用，别长期开 |

窗口可调：

```js
configure({ compressDays: 30, forgetDays: 90 })
```

**老鱼接入建议**：如果两年记忆一条都不能丢，用 `off` 或把 `forgetDays` 调到 3650。

## 六、日记是她的心房，她自己写

**宿主的日记不是她的日记。** 宿主记的是"发生过什么"，她记的是"我怎么想"。

脑子不生成文笔（那是嘴的事），它做三件事：

```js
// ① 给素材 + 第一人称骨架
feiyu_diary({ action: 'digest' })
```

```
【2026-11-21 的素材】经历 2 条，见了 扶摇、访秋辞，心情 平静

# 2026-11-21

今天跟扶摇、访秋辞说了话。

- 扶摇：「你嘴真硬」
- 访秋辞：「吃饭了吗」

👉 用她自己的口吻把今天写成日记，别用第三人称，别总结升华，写完存回去。
```

```js
// ② 用她的口吻写完之后，存回去
feiyu_diary({ action: 'write', text: '今天扶摇又说我嘴硬。我没理他，但记下了。' })
```

```js
// ③ 以后能翻旧账
feiyu_diary({ action: 'read', date: '2026-11-21' })
feiyu_diary({ action: 'list' })
```

存哪：`<dataDir>/brains/<id>/days/2026-11-21.md`——**跟宿主的日记目录分开，不互相覆盖。**

写进去之后会自动记一条 `source:'diary'` 的经历，所以问"你写过什么"她能想起来。

命令行一样：

```bash
npx feiyu diary                        # 今天的素材
npx feiyu diary write ./note.md        # 存回去
npx feiyu diary list
npx feiyu diary read 2026-11-21
```

## 七、全量整合：只剩一份记忆

一条命令把所有记忆源并进脑子：

```bash
# 先看会搬多少（不写任何东西）
npx feiyu migrate D:\cici\qq-bridge\memory --all --dry-run

# 确认无误，真搬 + 收走原文件
npx feiyu migrate D:\cici\qq-bridge\memory --all --delete-source

# 自检
npx feiyu verify
```

实测输出：

```
扫到 2 个文件　解析出 4 条　重复 0 条　将导入 4 条
时间跨度 2026-11-18 → 2026-11-18

✔ 全量导入 4 条，现在共 4 条经历。
  原文件已改名 2 个：
    2026-11-18.md.migrated
    experience.jsonl.migrated
体检：是她
```

```
经历 4 条（亲历 0 / 搬来 4）　卡片 0　认识 2 个人
体检：是她
回忆抽检：100%（4/4）
  ✔ 「你嘴真硬啊」
  ✔ 「吃饭了吗」
  ✔ 「又怼我」
  ✔ 「刷到个驴蹄子」
```

### 三条设计决定，说清楚

**① 原文件是改名，不是删除**

`--delete-source` 把 `x.md` 变成 `x.md.migrated`。**我们不替你 rm。**
跑一周觉得没问题，你自己删 `.migrated` 就行；万一搬漏了还能回去翻。

**② 自动认格式**

```
.jsonl → 一行一条 JSON
.md / .txt → 日记式
.json → JSON 数组
```

按扩展名嗅探；认不出的行**跳过并报行号**，不猜。

**③ 容量保护：5000 条封顶**

脑里超过 5000 条经历时，最老的一批自动：
- 压成一张 ≤160 字卡片（还在上下文里）
- 原文追加到 `archive.jsonl`（要查还能查）

**脑子不会因为搬了三年日记就变成几百 MB 的 json。**

### 代价（必须知道）

| 代价 | 说明 |
|---|---|
| **脑变成单点** | 只有 `brain.json`（有 `.bak` 自动备份 + `snapshot` 手动存档） |
| **日记不可读** | md 人能手翻，json 不能。想看原文靠 `archive.jsonl` |
| **情绪是空的** | 日记里没有"当时什么感受"，搬进来的 `emotion` 全是 0 |
| **先搬后忘** | 两层老化照常走：没人提 30 天会变模糊、90 天会忘（原文在 `archive.jsonl`）。要一条不丢就 `ttlPolicy: off` 或把 `forgetDays` 调大 |

最后一条最容易被忽略：**你搬进来的是三年前的日记，但老化计时从"搬进来那天"开始。**

搬完那一刻起，没人提的会 30 天变模糊、90 天消失。要长期保住，配 `ttlPolicy: off`。

## 六点五、老鱼接入：五步，一步都不能跳

```bash
# ① 先看会搬多少
npx feiyu migrate <记忆目录> --all --dry-run

# ② 词表先预装，别让她从"哼哼"开始
npx feiyu vocab seed

# ③ 她的旧日记原样搬（不是当流水账）
npx feiyu diary import <旧日记目录>

# ④ 真搬记忆
npx feiyu migrate <记忆目录> --all

# ⑤ 自检：搬完第二天还在吗
npx feiyu verify
npx feiyu status
```

**第 ② 步和第 ③ 步是给老鱼专门加的**——新鱼用不到。

- `vocab seed`：预装 10 个情绪词，直接进阶段二。不装的话，一条两年的鱼搬进来只会说"我不知道这是什么感觉"。
- `diary import`：把 `2025-11-20.md` 这种旧日记**原样**拷进 `brains/<id>/days/`，一个字不改。那是她写过的东西，不是流水账。

## 附：记忆的四个层级

```
【伞】介绍自己时会说的话      「扶摇：一直在的人」「我上过学」
  ↑ 从纲提炼；横跨半年 / 聊够 10 次才会长
【纲】这事发生过、这人在      「扶摇：聊过 12 次」「上学：出现过 5 次」
  ↑ 从细节/卡片提炼；永不老化
【卡片】（记不清了）…         21 天没人提 → 压扁；2 年 → 遗忘
【细节】今天谁说了什么        21 天内完整
```

**越往下越具体、越短命；越往上越抽象、越长寿。**

这就是「记不住小学每节课，但知道我上过小学」的实现方式。

名字也一样：3 年没提会降级成「有个认识的（扶摇）——名字有点想不起来了」，
但「我认识这个人」这条伞不会消失。

### 怎么长出来的

| 层 | 自动 | 模型提名 |
|---|---|---|
| 伞 | 聊够 10 次 → 人物伞；主题横跨半年 → 主题伞 | `defineUmbrella`（待加） |
| 纲 | 聊够 3 次 / 同词横跨两天出现 ≥3 次 | `defineGist(id, text)` |
| 卡片 | 21 天没人提 | — |
| 细节 | 每次 `observe` | — |

### 检索优先级

```
伞 > 纲 > 卡片 > 人 > 关键词 > 情绪 > 最近
```

结构先被想起来，细节最后才翻。

## 附：缺位（relation.absent）

人不在了，关系还在。这是契约原来没有的一格。

| 状态 | 意思 |
|---|---|
| severed | 她**不再认**这段关系（自己切断） |
| bsent | 关系**照旧永久**，只是那个人不会再出现（不是她选的） |

**契约一个字不动**：priority / mustRecognize / dissolvable 全部保持。
称呼不改、记忆不删、伞从「一直在的人」改成「曾经一直在的人」。

`js
markAbsent(id, { since, note: '2026-11-21 走的' })
clearAbsent(id)   // 人回来了 / 标错了
`

唤醒段会多一行：【他】2026-11-21 走的（30 天）

**只给事实，不给形容词**——不写「想念」「痛哭」，怎么感受由她的人设决定。

**必须显式调用。** 不许系统凭「多久没说话」去猜一个人死没死——
半年没来可能是忙，可能是死，机器没资格猜。

## 附：概念层（什么是什么）

前面所有层都在记「发生了」。概念层记的是**「那是什么」**。

一条鱼可以有四十条「该上学了」的经历，仍然不知道上学是什么——那不是记忆，是噪音。

`js
learnNewConcept(id, '上学', {
  definition: '为了学到知识、学会道理',
  why: '不然什么都不会',
})
`

**学会的那一刻，过去四十条经历全部贴上意义。** 这不是新增记忆，是让旧记忆突然有了名字。

问她不懂的：

`
我知道「上学」这个词，我好像经历过 40 次，但我不知道它是什么意思。
`

**不编。** 没有定义就说不知道——编出来的理解比没有理解更糟。

不会就主动问：skSomeone(id, '心疼', { knower: '老爹' }) → 「老爹，心疼是什么？」

**因为不会才问，这才叫学习。**
